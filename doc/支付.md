## 第 1 步 · 申领支付宝沙箱环境

1. 打开支付宝开放平台「研发社区/控制台」→ 顶部导航「开发者服务」→ **研发沙箱**（或直接访问 `https://open.alipay.com/develop/sandbox/app`）。
2. 记录沙箱自动生成的 **沙箱应用信息**：
   - `APPID`（形如 `9021000xxxxxxx`）；
   - 接口加签方式：默认已配 RSA2 公钥模式。
3. 进入「沙箱测试账号」页面，记录 **买家测试账号**（登录密码、支付密码分开展示，妥善保存）。

## 第 2 步 · 生成并配置密钥（最容易出错的一步）

1. 下载官方「支付宝开放平台密钥工具」（控制台-工具下载页）。
2. 在密钥工具中：
   - 填写账号别名 → 生成密钥对；
   - **密钥格式必须选「PKCS#1」**（本项目是 Node/Deno 环境，非 Java；选 PKCS#8 会导致签名报错）；
   - 生成后「应用公钥」复制到剪贴板，「应用私钥」妥善本地保存（不会出现在任何后台，丢失需重置）。
3. 回到沙箱应用页 →「接口设置/加签方式」→ 上传**应用公钥** → 提交后获得 **支付宝公钥**（注意复制的是"支付宝公钥"，不是你自己的应用公钥）。
4. 沙箱联调阶段无需在后台配置 `notify_url`（下单时由代码通过 `ALIPAY_NOTIFY_URL` 传入）。

**最终你应持有 4 个值**（沙箱一套、生产一套，绝不可混用）：

| 值 | 用途 | 环境变量 |
|---|---|---|
| 沙箱 APPID | 应用标识 | `ALIPAY_APP_ID` |
| 应用私钥（PKCS#1，纯 base64 原值，**不带** `-----BEGIN RSA PRIVATE KEY-----` 头尾） | 请求签名 | `ALIPAY_PRIVATE_KEY` |
| 支付宝公钥 | 验证通知/响应签名 | `ALIPAY_PUBLIC_KEY` |
| 沙箱网关 | 请求地址 | `ALIPAY_GATEWAY=https://openapi-sandbox.dl.alipaydev.com/gateway.do` |

## 第 3 步 · 注入 Edge Function Secrets

> 代码约定：任一必填 Secrets 缺失时，下单/回调函数直接返回 503（明确失败，绝不用占位值调 SDK）。

**CLI 写法**（若 supabase CLI 可连本项目）：
```powershell
supabase login
supabase link --project-ref <你的项目ref>
supabase secrets set ALIPAY_APP_ID=<沙箱APPID> ALIPAY_PRIVATE_KEY=<私钥原值> ALIPAY_PUBLIC_KEY=<支付宝公钥原值> ALIPAY_GATEWAY=https://openapi-sandbox.dl.alipaydev.com/gateway.do
```

**控制台写法**：进入 appmiaoda / Supabase 项目控制台 → Edge Functions（或"密钥/Secrets/环境变量"）→ 逐项添加上表 4 个变量。

补充两个联调变量（可后置）：
- `ALIPAY_SITE_URL=https://<你的域名>`（同步回跳基址，缺省则不回跳、仅查询兜底）；
- `ALIPAY_NOTIFY_URL=https://<SUPABASE域名>/functions/v1/alipay-payment-notify`（公网可访问后再配，缺省时代码自动省略该字段——这是设计内行为，不是错误）。

安全红线：私钥只进 Secrets，不写入代码/`.env` 提交版/文档/日志/聊天记录；`.env` 已被 `.gitignore` 覆盖。

## 第 4 步 · 执行数据库迁移（手动，必做一次）

`git push` **不会**自动变更线上库（本项目历史教训）。二选一：

- 控制台：SQL 编辑器 → 粘贴 `supabase/migrations/00026_alipay_webpay.sql` 全文 → 运行；
- CLI：`supabase db push`。

脚本幂等（`IF NOT EXISTS`），重复执行安全。成功后应存在：
- `orders` 新列：`pay_channel`、`alipay_trade_no`、`refunded_amount`；
- 新表：`alipay_notify_events`、`alipay_refunds`（均开启 RLS、无对外策略，仅服务端可读）。

## 第 6 步 · 沙箱端到端联调（核心验证）

### 6.1 启动与下单
1. 本地 `pnpm dev`，登录账号 → 进入 `/credits?tab=plans`。
2. 点击任一付费套餐「立即升级」→ 应整页跳转支付宝沙箱收银台（若弹出"已切换为手动扫码支付"的 toast，说明下单失败，按文末「常见问题速查」排查）。

### 6.2 完成付款（二选一）
- 方式一：在沙箱收银台输入 **买家测试账号 + 登录密码**，再输入 **支付密码** 完成付款；
- 方式二（仅 Android）：安装沙箱版支付宝 App，登录买家账号，在收银台用「扫码」入口付款。

### 6.3 结果核验（逐项记录证据）
付款成功后回跳 `/alipay-return`，页面应轮询显示「支付成功」。到数据库核验：

| 检查点 | SQL / 位置 | 预期 |
|---|---|---|
| 订单状态 | `select order_no,status,alipay_trade_no,paid_at from orders where order_no='<订单号>';` | `paid`、trade_no 已写入 |
| 积分发放 | `select type,action,amount,credits_after,description from credit_logs order by created_at desc limit 3;` | `purchase` + `plan_purchase/booster_purchase`，描述含"支付宝" |
| 权益生效 | `select credits_total,credits_used,status from user_plans where user_id='<uid>';` | 余额已增加 |
| 通知落库 | `select * from alipay_notify_events;` | 若配置了 NOTIFY_URL 应有记录（未配置则靠 6.5 查询兜底路径） |

### 6.4 异常场景回归（对应验证矩阵）
1. **取消支付**：收银台直接关闭 → 订单保持 `pending`，可再次下单；
2. **重复通知幂等**：对同一通知报文用 curl 向 notify 函数重放两次 → 第二次日志出现 `duplicate event ... skip`，`credit_logs` 不新增，仍返回 `success`；
   ```powershell
   curl.exe -X POST "https://<域名>/functions/v1/alipay-payment-notify" --data-urlencode "trade_status=TRADE_SUCCESS" --data-urlencode "out_trade_no=<沙箱订单号>" --data-urlencode "total_amount=<金额>" -d "<其余通知字段与sign>"
   ```
3. **篡改金额**：改 `total_amount` 重放 → 返回 `fail`，订单与积分不动；
4. **伪造 app_id / 错签名**：→ `app_id mismatch` 或 `signature check failed`，返回 `fail`；
5. **查询兜底**：不配 `ALIPAY_NOTIFY_URL` 完成一笔付款 → `/alipay-return` 轮询后订单转 `paid`、积分到账（证明通知丢失场景可自愈）；
6. **退款**（管理员账号）：调用 `alipay-trade-ops` `action=refund` → 仅 `fund_change=Y` 或退款查询 `REFUND_SUCCESS` 后 `refunded_amount` 增加；同一 `out_request_no` 重试不重复退。

> 通知联调（2~4 项）需要支付宝能真实回调到你时才有完整证据；本地阶段可用内网穿透（如 cpolar/ngrok/自定义域名，必须公网 HTTPS、无重定向）。暂时做不了就标记「公网通知待验证」，**不阻塞**开发与签约。

### 6.5 沙箱通过标准
验证矩阵 6 个场景全部有留证（订单号、字段查询结果、函数日志片段）后，沙箱联调视为完成，进入第 7/8 步。

## 第 7 步 · 产品开通（签约入驻，必须本人操作）

Windows 环境不支持 Skill 自动开通，请前往支付宝 AI 付站点人工完成：

1. 打开 `https://aipay.alipay.com` → 登录（企业账号）。
2. 选择产品「**AI 网页应用收款**」（旧称：网站支付）→ 提交开通。
   - 签约参数（页面会对应选择）：`productType=webpay`、`salesCode=I1080300001000041203`、`appType=PC_WEB`。
3. 按引导填写：主体资质（营业执照、法人）、经营类目（MCC，按实际业务：软件/SaaS/内容创作服务类）、网站信息与 **3 张截图**（第 0 步已准备）。
4. 提交后等待审核；审核通过后在「开放平台控制台-我的应用」创建**正式线上应用**，绑定「AI 网页应用收款」能力，重复第 2 步的密钥流程生成**生产密钥一套**。

## 第 8 步 · 切换生产环境

1. 替换 Secrets（六个值全部换成生产一套，缺一即 503 保护生效）：

```powershell
supabase secrets set ALIPAY_APP_ID=<生产APPID> ALIPAY_PRIVATE_KEY=<生产私钥> ALIPAY_PUBLIC_KEY=<生产支付宝公钥> ALIPAY_GATEWAY=https://openapi.alipay.com/gateway.do ALIPAY_SITE_URL=https://<正式域名> ALIPAY_NOTIFY_URL=https://<SUPABASE域名>/functions/v1/alipay-payment-notify
```

2. 在开放平台应用详情完成公网 `notify_url`/回跳域名相关报备（如平台要求）。
3. **最小回归**（真实小额）：下单 → 真机付款 → 收到验签通过的通知并返回 `success` → 订单 `paid` + 积分到账 → `/alipay-return` 展示正确 → 发起一笔退款并查询确认。
4. 对账习惯：每日核对 `orders(status=paid)` 与 `alipay_notify_events`/`trade-query` 结果一致性；差异一律以服务端查询为准补偿，不要求用户重复付款。

## 常见问题速查

| 现象 | 处理顺序 |
|---|---|
| 下单报 503「支付宝支付配置未完成」 | Secrets 未注入/变量名拼错 → 第 3 步补 |
| 跳转收银台报「无效签名 invalid-signature」 | ① 私钥是否为 PKCS#1 纯原值（无 PEM 头尾）；② appId/公钥/私钥是否同一套；③ 网关与 appId 是否沙箱/生产匹配 |
| 付款成功但订单仍 pending | 未配 `ALIPAY_NOTIFY_URL` 或未部署 notify 函数 → 先由 `/alipay-return` 查询兜底，再按第 6.2 步补公网通知 |
| 通知到达但返回 fail | 查函数日志：`app_id mismatch`/`signature check failed`/`business check failed`（金额或卖家不符）→ 对照第 3 步配置 |
| 回跳 404 | 域名 rewrite 未覆盖 SPA 路由（vercel.json 已有 `/(.*)→/index.html`；自建网关需同样配置） |
| 退款后金额没变化 | `fund_change` 非 `Y` 属"结果未知"→ 等 ≥10 秒用原 `out_request_no` 调 `refundQuery` 确认 |
