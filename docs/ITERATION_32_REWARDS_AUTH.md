# 迭代32：邀请账本、活动回执与账号恢复

日期：2026-10-22。新增00060，production预检升级probe20/required_migration=00060，render4/edit2及MCP59工具/19权限保持。本地源码与隔离验证不代表目标环境已上线。

## 行为与数据

- 邀请表、邀请码及注册奖励此前仅在旧schema快照存在，本轮加入正式增量。接管旧注册/邀请触发器，消除顺序依赖；保留既有邀请码与历史记录，仅补齐缺失邀请码。浏览器不能插入注册档案、改邀请码或改奖励表。
- 免费注册原子创建档案、套餐和一笔20积分流水。有效邀请码在注册时绑定已验证、未封禁邀请人；新账号完成邮箱或手机验证后，双方各增加50总积分，并各写一笔唯一奖励流水，不冲减已用积分。双账号按UUID锁序、邀请行与流水在同一事务；流水故障会回滚验证事件并允许原事务重试。
- 新邀请标记reward_version=1；旧记录保持NULL版本，绝不自动补发。旧流水仍原样保留；新页面“已确认奖励”只汇总新协议可核对入账，“历史待核对”不被解释为新的到账承诺。邀请无效或邀请人封禁时不阻止注册，也不会发放邀请奖励。
- get_my_invitations只接受分页参数，auth.uid决定本人范围；数据库聚合完整记录，20条一页、最大50条，避免Data API1000条上限。受邀人仅显示遮蔽标识，不开放其档案/邮箱。移动端逐条显示时间、状态与入账，桌面保留表格。
- 复制需等待真实剪贴板回执；邀请码未读取时禁用分享，不生成空链接。二维码直接从本次邀请URL生成；海报含20积分注册与验证后双方50积分规则。生成/缓存按账号与URL核对，不读取全局重复DOM ID。
- 活动资格和领取共用数据库判定：开始/结束、正奖励、限次、UTC日、历史缺时间待核对、后台完成且有成片/原扣费结算的video_jobs。客户端完成项目不作为首次视频凭证。社区等未接入可信凭证的活动明确要求支持核验，不自动发奖。
- claim_activity_reward(activity_id,request_key)保存不可变回执与活动/日唯一流水；同一个请求在活动结束或奖励调整后仍返回原奖励。无原请求的重复领取拒绝，独立回执也阻止仅回拨汇总时间重领。浏览器按账号先保存原UUID，丢失响应或刷新后“恢复原领取”，只提示实际回执。
- 活动与邀请查询失败显示错误及未知/上次结果，可刷新；领取串行，旧账号迟到结果不提示给新账号。敏感POST/PUT使用发起账号的实际Bearer令牌，与SDK全局会话切换隔离；令牌仅在请求内存，不写入本地草稿或回执。
- 注册页删除浏览器档案upsert，标准化携带的邀请码；身份服务隐藏已注册邮箱的场景只提示查收验证邮件/直接登录，不冒充已新建账号。登录检查真实会话，宣传页去除未经验证的8k/10x/20分钟指标。
- 新/auth/reset入口承接恢复会话，验证当前账号后更新密码；失败保留输入，成功核对返回用户并清空密码。旧/login?mode=reset转到新入口，账号切换重建表单，失效链接可重新申请。邮件重定向白名单及真实身份服务仍需目标验收。
- ErrorBoundary上报使用受控report_frontend_error原UUID回执，失败保持可重试，不显示已提交。只上传路由路径和固定异常码，不上传查询串、哈希、堆栈或密码。数据库限制本人每分钟10份并禁止浏览器直接伪造日志；记录提交不表示已发外部值班消息。
