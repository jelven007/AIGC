# 业务后端与运营后台开发方案

更新：2026-10-22，功能基线`d7e3d38`。当前后端为Supabase Auth/PostgreSQL/Storage/Deno Edge，运营UI使用现有React `/operations`，客户工单为`/support`。`backend/`保留历史规格，缺核心源码，不是当前已运行的Spring Boot/Vue中台。

## 1. 已有业务后端

43生产入口及共享模块支撑视频/production租约任务、商品管理、知识、情报、发布/观测、支付/运营。关键创建固定原UUID/完整输入/配置版本/价格/原流水，确定失败一次补偿；unknown不重发，checkpoint只恢复原结果。当前00062/probe22/render4/edit2、20模型槽、MCP59/19，官方最近成功证据00031/三旧函数，最新目标未部署。

## 2. 后台范围与权限

| 模块 | 当前交付 | 边界 |
| --- | --- | --- |
| 用户/套餐/预算 | 真实分页、本人与可信客户范围、个人/团队UTC日预占预算、欠额 | 失败不伪零，退款不抹预算；企业统一付款未交付 |
| 模型 | 20槽加密不可变版本、管理员双校验、只读test、旧任务绑定 | 无Key/密文回传，模型名称不证明账号权限 |
| 任务 | 视频/媒体/分析/知识/情报/翻译/多镜头阶段与发布组 | 原证据/租约/UUID，不直接改终态或上游受理 |
| 工单 | 归属关联、10未结案、分配/公开回复/内部备注/版本/原UUID | 内部消息过滤，原请求恢复仍校验当前范围 |
| 租户 | 所有权/成员/容量/启停/团队预算版本 | 全客户范围权限，已签链接原期限仍有效 |
| 风险 | 原事件人工结论、新计费限制/解除/原因/审计 | 两者独立，原退款/工单/任务恢复不受新限制 |
| 财务 | 两渠道原申请/预占/签名到账/权益回收、原调用分币种现金/凭证/冲销 | 未核对不计零，不自动发票，真实渠道待验收 |
| 告警 | 原对象规则/范围/接手/恢复/再发生/采集时间 | 独立monitor，审计只读，外部值班通知需配置 |

授权来自服务端Auth元数据或operator_grants及实际客户范围；profiles.role/user_metadata/客户端header不授予权限。API Key不开放运营和支付管理，service_role只在受控服务端使用。

## 3. 数据与事务契约

全部运营写通过operations/RPC，固定原UUID、完整参数、expected版本、原因与审计；撤权后旧请求也拒绝。列表分页25条，当前operations正文16KB/用户60次每分钟；资金30次/分钟，具体契约见 [API](API_AND_DATA.md)。

统一扣费锁序为套餐→用户团队锁→用户风险锁→团队行；现金权益按账户→订单→退款。原charge固定创建时团队/周期，最小货币单位与币种分开，退款预占与签名到账回收同事务，现金账本只追加。00057修复00056锁序，不修改旧迁移校验值。

媒体引用索引/对象锁、租约outbox/删除墓碑、知识/声纹副本清理复用production调度。独立monitor与持久卷不执行退款；加密恢复保留Auth/DB/Storage/回执/扩展/历史密钥，unknown不退回queued。
