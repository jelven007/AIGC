# 迭代33：权威积分权益与短信会话

日期：2026-10-22。新增00061，production协议为probe21/required_migration=00061，render4/edit2与MCP59工具/19权限保持。本地交付与隔离测试不代表目标上线。

## 余额与套餐

`get_my_credits()`只读取`auth.uid()`本人，管理员也不能借此查询他人。一个快照返回积分总额/已用/可用、套餐ID与名称、配置等级/有效等级、状态、到期时间、周期和服务端时间。缺少积分账户明确报错，不伪造零余额或免费套餐；读取不重置历史资金。

有效权益遵循现有后台批量任务口径：`status=active`且未到期或没有到期时间。套餐门禁按等级识别，专业入口要求至少1；名称包含“专业/企业/pro”不会授予权益。过期套餐保留实际积分余额，套餐页允许重新选择原套餐，不再标为当前生效。免费基础权益不宣传按月重复赠送积分。

顶栏、弹窗、个人中心、计费页和门禁共用账号范围React Query查询。AccountScope只建立一份Realtime订阅；本地入账事件、可见页30秒轮询和窗口恢复回源刷新。同账号查询失败保留上次快照但标记不可核验；门禁提供重试，不能把付费用户误导到升级页面。换账号销毁缓存、取消读请求，旧结果不污染新账号。

过期判断根据服务端时间和浏览器单调时钟经过时长，在页面内到期也立即移除权益。发起生成时重新读取权威余额并复核会话；实际扣费继续由后台创建事务负责。移除无调用的浏览器扣款/退款遗留函数及模块全局余额缓存。

## 短信与账号恢复

短信明确区分已有账号登录和新账号注册，登录传`shouldCreateUser=false`，不会意外创建用户；注册携带标准化邀请码。中国大陆号码支持本地号码、空格与+86，其他地区要求E.164国际号码；验证码要求6位数字。发送和验证使用同步忙碌锁，验证始终绑定原手机号。

短信验证使用不持久化的独立SDK客户端，请求有15秒上限并在离页取消。核对会话用户/原手机回执及当前页面仍匿名后才交给全局Auth。错码保留输入；离页后的验证结果不自动登录。成功跳转由AuthProvider完成，保留允许的原`redirect`。

明确发送失败可重试；5xx/网络错误不宣称发送成功，保留原手机和验证码入口，60秒内禁重发。用户已收到验证码时可继续验证。短信服务商配置、验证码长度和服务端限流仍需目标Auth验收，浏览器限流不能代替平台控制。

邮箱表单增加同步防重和离页/模式变化结果保护。公开首页“查看套餐与权益”携带允许的计费页回跳，登录后返回套餐选择。通知读取和标记/清理/偏好请求固定发起账号令牌；换账号和详情离页不显示旧通知操作提示，失败保留真实未读结果。

## 正式协议资源

经营方必须提供`VITE_TERMS_URL`和`VITE_PRIVACY_URL`的可阅读正式HTTPS文档。链接可独立打开且不触发勾选。缺少任一资源时，新账号注册不可提交，已有邮箱/手机号仍可登录。仓库不编造经营主体或法务批准文本，客户端勾选不作为可信法律审计记录。

火山部署`prepare`构建要求`--terms-url/--privacy-url`或对应环境变量，记录链接到前端构建回执；`pages`核对回执，避免部署未配置协议的注册页面。`prepare --skip-build`仍可独立准备数据库迁移。链接格式通过不表示内容经法务批准或当前可访问。
