# Bug: 空脚本误报草稿恢复，状态提醒占用编辑区域

> Status: FIXED
> Mode: default
> Severity: functional
> Last updated: 2026-11-01

## Symptom

进入视频分镜脚本页面后显示“已恢复上次未完成的草稿”，即使没有填写过内容。用户要求同类提醒改为浮层弹窗。

## Expected

只有有效的创作内容或主动修改的参数才属于草稿。关闭恢复提示保留内容；状态提醒不占页面布局，待处理操作可以收起后重新展开。

## Reproduction

- 打开 `/script`，不输入内容，刷新；原逻辑会显示恢复提醒。
- 缓存为空表单或只有空白字符时，同样误报。
- `tests/browser_script_notices.mjs` 三个空草稿用例在修改前全部失败；通过测试拦截重新加载原始 Vite 草稿模块后，三个用例再次全部失败。工作区修复始终保留。

## Hypotheses & diagnosis

| 假设 | 结论 | 证据 |
| --- | --- | --- |
| 页面初始化保存默认表单，随后按缓存键存在判定恢复 | confirmed | 从无缓存开始进入和刷新仍失败；自动保存 Effect 与 `hasDraft` 初始化形成完整因果链 |
| 仅由用户已有历史草稿导致 | eliminated as sole cause | 全新独立浏览器上下文、没有任何草稿时仍可复现 |

## Root cause

`ScriptPage` 挂载后自动保存默认表单。`useDraft` 以 localStorage 键是否存在判定草稿，未校验内容、空白或格式，因此空表单也被当作可恢复内容。旧提示的关闭按钮还调用了清空草稿，与关闭提醒的预期不一致。

## Fix

- `apps/web/src/lib/scriptDraft.ts`：兼容历史缺省字段，校验类型并判断内容是否有效。默认表单、空白内容及无效结构不会恢复；部分创作内容和主动修改的参数仍可恢复。
- `apps/web/src/hooks/useDraft.ts`：读取和写入共用校验；无有效内容时不保存空草稿。离页保存与账号原键继续保持。
- `ScriptPage`：真实草稿恢复用短时浮层提示；关闭只隐藏。通过“新建脚本”的确认弹窗明确清空本地草稿。
- `FloatingNotice`：统一浮层显示。带操作的提醒持续保留，关闭时缩成浮层入口，可重新展开；处理结果仍调用原业务函数。
- 草稿、知识引用、素材、批量生成、导出、发布、商品、情报、媒体任务、实验、奖励和邀请码的同类状态提醒迁入浮层。
- 全局 Sonner 放入路由及账号上下文，浮层中的继续创作链接可正常导航。商品编辑对话框打开时，页面恢复提醒暂时隐藏。

## Pattern analysis

`useDraft` 当前只有脚本页面一个调用点。另扫描并迁移了页面顶部同类临时状态提醒。已有确认弹窗中的内容、表单字段与任务详情继续使用各自的业务界面。

## Scope

本轮修改本地源码并验证实际页面；未更改用户保存的服务端脚本、待确认请求标识或数据库结构。
