# 迭代27：多镜头配音合成与发布编排

本轮在本地接通 `/batch-create` 的多镜头生产链。每商品生成2–6个镜头，使用用户确认的目标语言台词配音，FFmpeg测量完整音轨，可选Whisper真实时间分段字幕，随后合成私有成片和可编辑工程。选择发布交付后，先等待实际成片预览，再按原阶段UUID进入现有多账号发布队列。代码与测试交付不代表目标环境已上线。

## 持久任务与计费

- `00055_batch_production_pipeline.sql` 新增阶段回执、依赖、原UUID、配置版本与原扣费流水，兼容00038单视频批次。创建事务锁账户，验证有效套餐、全部商品、当前价格、整批余额与预算；任一步失败整批回滚。
- 单商品价格为 `镜头数 × generate_video + generate_tts + 可选 generate_edit_subtitles`；合成和无字幕音轨测量不收应用积分。供应商实际用量和现金成本仍需独立对账。
- 等待依赖的配音和字幕先保留预算，开始执行时复用原流水，不按后续新价格再扣费。全部供应商版本在创建时绑定，重试已有批次不重新读取商品、模型开关或价格。
- 媒体10项、剪辑分析3项、渲染24项的执行名额与原功能共用。待依赖阶段不提前占执行名额；候选领取过滤已满账户，避免其等待项阻塞其他可执行任务。新旧批次共用5个活动批次上限。
- 暂停阻止后续领取；已启动、已受理和未知请求继续恢复原证据。取消仅释放尚未提交的镜头及尚未启动阶段，逐笔原流水退款。退款事务失败保留原状态并可重试；已受理配音、镜头、合成和发布不会因取消而伪造退款。
- 跨账户控制在修改前拒绝；阶段表、依赖视图及编排RPC仅服务端可用。进行中和待发布的最终工程禁止用户删除或伪造状态。

## 实际媒体与发布

`batch-pipeline.ts` 只使用已完成的私有依赖。镜头按原位置拼接并静音，配音使用实际音轨长度，字幕使用真实起止时间。无字幕模式仍经过免费音轨测量。配音超过确认的镜头总时长会明确失败，不截断台词，也不按字数编造时长。镜头实际素材过短由现有FFmpeg校验拒绝，已受理镜头的费用不能冒报返还。

当前每镜头沿用模型允许的2–15秒规格，最终720P/1080P、30fps，最多70段字幕和80个轨道。后台协议支持已接入转场，当前页面默认直接切换镜头。用户需提供供应商有效音色ID和目标语言正文；这里不自动生成或翻译事实台词。

发布页面从批次入口携带成片、商品子项和原发布阶段UUID。真实预览源、账号权限、逐账号可见范围及商业/AIGC声明沿用既有校验，发布组创建和阶段绑定在同一事务内完成。断线后恢复同一发布组；成功账号不重复派发，未知受理保留核对，暂停和取消同样约束尚未提交的发布子任务。

## 网页与MCP

网页新增镜头要求、配音台词、音色、字幕和交付方式；显示逐阶段价格、预占、结算、返还及成片/发布入口。合成回填完整轨道名称与编辑画幅，重新打开可以保存并恢复原镜头、配音和字幕。会话回执写入成功后才提交，503或异常响应保留原请求；关闭页面由生产调度继续推进。

MCP新增 `submit_batch_pipeline`，需要独立 `batch:create` 权限，避免通过单视频权限触发配音和合成。`submit_publish_group` 支持 `batch_item_id`，需使用快照中publish阶段原UUID和真实预览源；发布仍需明确用户授权。工具目录现为59个、业务权限19种。
