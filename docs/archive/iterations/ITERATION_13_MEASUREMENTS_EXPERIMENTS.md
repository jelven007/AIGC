# 统一观测报告、授权数据接收与对照实验

日期：2026-10-21。新增迁移 `00042_measurements_experiments.sql`、`measurements`、`measurement-ingest`。这是本地交付，未部署云端，未声称已获得广告平台或交易数据权限。

## 用户功能与真实口径

- `/analytics`、`/data-dashboard`、`/data-feedback`共用一个报告接口，删除随机指标、预置作品、行业均值、概率预测和固定优化提升。页面读取不会自动调用收费模型。
- 官方自然视频统计所选UTC日期区间内发布的视频，以平台/账号/视频去重取最后累计快照；不累计历史快照，不冒称区间新增播放或去重观众。播放、点赞、评论、分享展示已观测视频覆盖数；真实0显示0，缺失显示「—」。
- 投放与交易通过已获授权的采集服务发送签名观测；按数据源及币种分别汇总，不叠加不同数据商的重合归因。每个数据集/业务日期使用递增版本的绝对快照，更新替换旧值。CTR=点击/曝光，CVR=转化/点击，CPA=消耗/转化，ROAS=(GMV−退款)/消耗。0分母和任何所需字段缺失时不计算；未接商品成本、税费、履约等，利润ROI未知。
- 支持CNY/USD/EUR/GBP/SGD/HKD/AUD/CAD，金额使用整数分（最小货币单位，两位小数）。本契约是同日、同数据集的可比较漏斗，要求转化≤点击≤曝光、退款≤GMV；独立归因窗口或多事件转化不能不加转换地导入。
- 报表保留创建趋势、风格、时长和作品明细，按全部匹配数据在服务端汇总。作品明细最多100条，自然视频明细最多500条、采集错误100条，风格最多50类；明细上限不改变概览总量。Excel导出实测指标及来源、时间与上限，不输出旧预测字段。汇总超过JS安全整数时显示缺失。
- 创意建议需主动输入背景、选择作品并确认当前价格（默认10积分）。服务端校验价格和归属，只把背景及服务端观测交给模型，拒绝客户端经营指标；输出建议而非“已经优化完成”。用户可带入脚本或剪辑，效果需独立实验验证。

## 实验协议

`/ab-test`预注册2–8个已完成私有作品、主指标、每组100–1,000,000曝光用户样本和结束时间，A为对照，最多10个未结案实验。请求UUID和完整规格一起保存，创建失联/刷新用原请求恢复；启动后不允许修改规格。

实验与授权数据源绑定；签名`assign`按服务器等比例随机分组，保存匿名64位十六进制用户摘要、变体和分组时间。相同用户重试不重抽，返回变体/作品ID，不返回私有视频URL。投放服务须按这个分组实际展示内容，再发送`exposure/click/conversion`；自然平台视频指标不是随机实验样本。用户摘要由采集服务使用稳定盐产生，禁止传原始邮箱/手机号或其他用户标识。

事件支持每批1–100条，需先分组、再曝光、再点击、再转化；时间不得早于分组或晚于预设窗口。每用户每阶段最多一次，不按事件请求次数累加。24小时接收延迟期允许补发窗口内事件；不把窗口外转化混入结果。事件顺序错或任一行无效时整批回滚，修正后按新正文生成新请求UUID。

投放窗口结束及24小时回流后才可结案；草稿可关闭不产生显著结论。所有组满足最低样本量、完整曝光以及样本比例检查后，按预注册CTR或转化/曝光进行双尾两样本比例检验。期望成功/失败单元少于5时不做正态近似。多组对照比较采用Holm校正，0.05阈值，各组显示Wilson 95%区间；CVR仅描述点击后转化。对照为0时相对提升缺失，不显示“无限提升”。低于0.01 Bonferroni阈值的对照/变体分组比例异常会拒绝结论。

显著改善只是该实验内的统计观察。未交付平台广告原生实验创建、自动淘汰/投放调价、模型训练或未经确认的自动发布。

## 鉴权、签名与事务

`measurements`的report/experiments/sources/projects/advice-price支持JWT及`metrics:read` Key；写实验和管理数据源仅JWT。来源登记/停用同时验证Auth管理员和数据库管理员身份。可给指定user_id登记数据源，前端管理自己的来源。签名密钥AES-GCM加密，密钥摘要仅用于登记幂等比较，二者不回传；新密钥使用新来源ID，停用不影响历史报表。每用户最多20个启用来源。

所有接收表和实验表开启RLS，撤销anon/authenticated直读写；仅业务API使用service_role和限定RPC。旧ab_test_variants保留历史数据并撤销客户端写计数权限，不将其迁入新实验样本。

采集地址`${SUPABASE_URL}/functions/v1/measurement-ingest`需关闭网关JWT验证；函数内部必须验证以下请求头，不能通过用户JWT/API Key绕过：

| 请求头 | 内容 |
| --- | --- |
| x-measurement-source | 管理员登记的来源UUID |
| x-measurement-timestamp | UTC Unix秒，允许±300秒 |
| x-measurement-signature | HMAC-SHA256(secret, timestamp+"."+原始UTF-8正文)，小写hex |
| Content-Type | application/json |

正文最多128KB；三种action都需要固定request_key UUID。`assign`再传experiment_id/unit_hash；`events`传experiment_id及events[{unit_hash,type,occurred_at}]；`daily`传rows[{project_id,dataset_key,business_date,revision,currency,impressions,clicks,conversions,spend_minor,gmv_minor,refunds_minor,observed_at}]，所有计数字段必须明确非负安全整数或null。

来源行锁串行化本来源写入，观测/分组/事件与(source_id,request_key,body_hash,response)回执一起提交。原正文重放返回原响应，正文变化409；重试重新签当前timestamp但保持正文/UUID。旧数据版本、跨用户作品、变更归属、过期窗口和不合法漏斗拒绝，HTTP409不表示旧请求未受理。签名/停用401、正文400、体积413、限流429、依赖503。来源500请求/分钟；报告/管理每用户90请求/分钟，限流服务故障拒绝。
