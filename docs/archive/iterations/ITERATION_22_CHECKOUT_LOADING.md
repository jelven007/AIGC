# 迭代22：真实收银入口、账单与前端加载

2026-10-22，本地增量00050；最近核验的官方云端仍00031/三个旧函数，未部署本轮收银协议。资金测试使用隔离PG16，浏览器使用受控HTTP和Chromium，未向真实商户下单或付款。

## 行为与架构

- 删除全局弹窗中的硬编码套餐、演示流水、任意兑换码到账、固定积分货币比率/已赠分/成片数量承诺。积分不足仍打开真实余额弹窗，用户可以进入现有套餐、流水和订单页；余额加载失败显示不可用，不把读取失败当零余额。未登录生成和余额未知不放行。
- 积分页只读取本人套餐、实际流水和订单；区分读取失败与空记录，支持重试、真实总数、服务端分页和稳定排序。使用率分母是账户credits_total，包含加油包/奖励；余额下限为零。React Query按用户隔离，旧余额响应不能覆盖新账号，相关读请求15秒限时。
- 唯一收银弹窗要求真实套餐、金额、积分和渠道确认；支付宝失败不再回退个人静态二维码。删除pay.png和个人微信引导。公开首页删除静态价格、无限配额/退款承诺，购买按钮进入登录后的真实套餐页；登录回跳只允许预设的套餐地址。
- 新支付POST输入为`{plan_id,request_key,expected_amount,expected_credits}`，金额是两位小数文本、积分为整数。浏览器先保存按用户隔离的原请求，存储不可用不POST；unknown保留原套餐/渠道/金额/积分/UUID，刷新后继续恢复，已知拒绝返回最新套餐重新确认。关闭弹窗可以从订单页核对。
- `begin_checkout_order`仅service_role执行，核验真实账号/封禁状态，按账号锁检查同UUID原参数和当前套餐价格/积分，创建订单及原权益快照，最多10个待支付订单。同请求并发只有一个本地订单；原请求在套餐改价之后仍恢复原金额/权益，跨用户相同UUID是独立订单。价格相同但积分变更也拒绝新请求；32位随机商户订单号满足微信长度限制。
- 两渠道共用该事务。支付宝使用原订单号/快照名称/金额生成pageExec POST表单；浏览器只复制签名hidden字段到新表单，限定HTTPS官方网关，不执行返回HTML里的脚本。微信使用原商户订单号、人民币分值和15秒SDK超时；已保存支付地址直接复用。供应商或地址入库失败返回unknown与已知原订单回执，不泄漏内部错误。
- 已完成订单恢复只返回本地终态，不重复发起收款。付款仍由已有验签、金额核对和`finalize_paid_order`事务入账；显示二维码、点击按钮和同步回跳均不作为成功证据。支付宝NOT_EXIST保持待确认；退款终态不会显示为付款成功。
- 订单详情按本人ID读取，5秒一次、最多24次自动核对，不重叠轮询；达到上限可以手动核对，服务端支付通知继续工作。当前微信依赖验签通知与本地订单查询，主动官方查单/关闭/过期处理及原路退款仍待后续交付。
- 应用布局只在登录后的业务路由加载，React/Supabase/Query拆成共享文件，图表/剪辑/导出依赖保留动态入口。Vite预构建缓存按模式与后端主机隔离，忽略验证产物目录，解决多本地服务覆盖缓存导致脚本URL返回HTML的空白页。

## 发布与后续

发布需同窗口应用00032–00050，更新两支付创建函数、共享checkout、production-worker/调度器及前端；probe v11/00050/render2，MCP仍54工具/18权限，资金入口不开放Key。旧支付客户端缺少UUID/金额会被拒绝，不能单独更新某一端。
