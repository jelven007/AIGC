# 迭代28：工单、租户策略、风险处置与现金成本

2026-10-22。本轮在现有React和Supabase事务层交付运营流程，迁移00056、production probe17、render4/edit2，MCP仍59工具/19业务权限。本地实现与隔离验证不等于目标部署和正式业务验收。

## 工单与客户入口

- `/support` 为所有登录客户提供真实工单创建、问题分类、原任务或订单关联、分页查看及回复；每人最多10条未结案工单，重新打开也核对容量。
- `/operations` 按客户范围查看工单、分配有该范围权限的处理人、设置优先级、公开回复或内部备注，执行待处理/处理中/等待客户/已解决/已关闭流程。
- 普通客户可回复未关闭工单，确认关闭或重新打开已解决工单。内部备注只向有工单读取权限的运营身份返回；关联对象在数据库核对原归属。
- 每次变更保存原UUID、完整参数、记录版本和审计。相同请求只落一条消息；不同请求持旧版本返回冲突，503/刷新恢复原参数，撤权后原请求也不能绕过当前权限。
- 响应期限按普通24小时、紧急4小时、低优先级72小时设置。这是处理目标，自动逾期告警另行接入。

## 租户与团队预算

- 全部客户范围的运营/管理员可查看分页成员名册，调整团队名称、启停、成员上限、团队日预算，并将所有权转移给当前有效成员；所有者角色与团队所有者在同事务修改。
- 可调整非所有者成员角色或移除成员，拒绝已移除成员与直接修改所有者；成员变更和团队策略均推进租户版本。
- 暂停阻止新的计费任务、团队邀请接受和新的团队共享读取/签名。原已受理任务、积分返还、现金退款与工单仍按原证据恢复。已签发Storage链接在原有效期内仍可能访问，暂停不能撤销其签名。
- 扣费采用用户团队串行锁→团队行→用户套餐行。团队预占账本保存原charge_id和创建时团队；多人并发不能超预算，退积分和移除成员不抹除当天预占。
- 团队预算按UTC日统计自00056启用后的预占。费用与套餐仍归提交人，本轮未实现企业统一付款账套或转移个人作品所有权。

## 风险处置

- 风险人员按客户范围将原事件标记为核查中、排除或确认，并记录原因、版本、处理主体与时间。
- 新计费任务限制与事件结论独立。运营人员明确限制或解除客户后，统一扣费事务拒绝新的消费；客户仍可看原记录、提交工单申诉，原流水退款不受影响。
- 个人资料角色不参与授权，JWT由服务端解析，API Key不开放运营管理。角色撤销、账号禁用和客户范围均在实际数据库操作时校验。
- 统一新计费策略拒绝回执：账号/租户限制为403，UTC个人/团队日预算为429；视频、图片、媒体、字幕/分析、批次、知识、情报、翻译和同步文本保留真实原因。前端清除未受理请求，原请求恢复时仍用原UUID核对；预算耗尽不打开充值弹窗，网络和受理未知继续保留原证据。

## 供应商现金成本

- 财务从“待核对现金用量”定位原视频/生产/同步模型调用，按实际账单登记供应商、账号、账单号、行号、币种、金额及原凭证SHA-256；网页可从实际本地文件计算指纹，原件由企业档案保留。
- 归属、模型版本与供应商由数据库从原调用读取，客户端不能伪造；账单编号应包含供应商/账号，账单行全局去重，跨模型版本也不能重复记同一行。
- 金额以最小货币单位保存；有实际凭证的零成本可人工登记。未登记调用显示“尚未核对”，不自动视为零，不按应用积分推算现金。
- 账本只追加，禁止覆盖或删除。冲销绑定原entry_id、原币种与完整原金额，最多一次；新冲正用新的账单行和凭证，积分不变。
- 分币种汇总全部授权范围的账单与冲销，不混合币种。人工登记表示财务确认，不是系统自动拉取或验签供应商发票；自动账单连接器和实际发票核对仍需供应商权限。
