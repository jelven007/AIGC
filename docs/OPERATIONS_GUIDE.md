# 运营与客服手册

版本：2026-10-21。产品范围见 [PRD](prd/PRD.md)，实际部署见 [当前状态](CURRENT_STATE.md)。现阶段进入受控试点准备，尚无真实模型规模、付费用户、转化提升或利润率的验证结论。

## 1. 责任与试点准入

| 责任 | 日常工作 | 交付记录 |
| --- | --- | --- |
| 产品 | 范围、交互、价格展示、接受条件 | PRD/需求 ID、发布范围 |
| 模型管理员 | 供应商权限、接口设置、版本与禁用 | 槽/配置版本、只读检查、真实生成验收 |
| 运营 | 招募、培训、质量反馈、用量预算 | 试点名单、授权素材、成本与接受原因 |
| 客服 | 工单、任务说明、支付/积分反馈 | 用户/任务/订单 ID、证据、处理结论 |
| 财务 | 支付权益、积分与供应商账单对账 | 差异清单、原因、冲正/补偿凭据 |
| 运维 | 环境、调度、监控、发布与恢复 | 运行记录、故障时间线与回归证据 |

这些是流程职责，完整后台 RBAC 和工单系统尚未交付；当前由受控管理面和脱敏记录执行。客服不取得 service_role/模型密钥，不直接修改数据库金额或积分余额。

试点前必须部署匹配后端、配置管理员和模型、通过所启用能力的云端用例、确定供应商用量上限与试点停止条件。私有素材源码已新增，最近云端仍需迁移与签名访问验收；此前不接收要求私有存储的客户内容。支付未经沙箱与商户验收时不开展正式充值宣传。

## 2. 用户上手与培训

1. 登录并核对本人资料、套餐/积分；邮箱需验证时完成邮件流程。
2. 准备有使用权的商品描述和素材；明确商品事实、卖点、受众、语言与禁用表达。
3. 选择已启用模型和支持规格；先用小样本确认质量，再提交正式任务。
4. 视频提交记录任务标识，可关闭页面；重新登录在任务/作品查看结果。收起进度不是取消，重复点击不能创建新幂等键。
5. 完成后检查画质、商品一致性、文字、音频与版权，再下载使用。新源码支持FFmpeg剪辑和抖音/TikTok逐账号授权发布；启用须分别完成容器、应用权限与账号联调。其他平台与无人审核全自动分发未交付。

新图片/封面已有持久化任务与关页恢复，归档失败复用原结果，受理未知先核对。文本和音频仍为同步辅助；超时先核对是否已有结果/供应商记录，避免重复付费调用。范围见 [生产链路](ITERATION_06_PRODUCTION_PIPELINE.md) 与 [功能覆盖](FUNCTION_COVERAGE_REVIEW_20261021.md)。

访问控制新版发布后，旧API Key需重新签发并选择所需权限/有效期；密钥仅显示一次，客服不索取。团队邀请须由对方使用已验证的指定邮箱接受，不会自动成为成员；共享资产仅明确选定的素材，任务积分由提交者承担。移除成员和撤销共享阻止新签名，已有签名可用到期限。素材被工程/任务引用时不能删除；已受理删除由后台清理存储，故障可重试。完整事实和上线条件见 [访问控制迭代](ITERATION_08_ACCESS_CONTROL.md)。

批量生成在有效专业版/企业版下每批1–50个商品、最多5个活跃批次，一商品一条视频。创建先确认真实单价与整批预占，响应未确认时恢复原请求；暂停仅阻止后续提交，取消只释放未提交项。已受理/待核对不能承诺取消退款，部分成功按子任务分别结算；语言与风格是模型提示，字幕/配音/混剪需后续加工。完整事实与验收见 [批量迭代](ITERATION_09_BATCH_VIDEO.md)。

多规格导出可选择六画幅（含4:5）/三短边，最多18组合，全部后台独立编码、下载和确认发布。受理失联用“恢复上次导出”，不换键；旧单规格回执可恢复并在任务中心看结果。队列满等待，部分失败保留成功成片。render当前不扣应用积分，但有FFmpeg/Storage/带宽成本，正式定价与资源预算需实测。官方Sora已关闭，不能作为可售模型；详见 [迭代10](ITERATION_10_RENDER_EXPORTS.md)。

## 3. 客服状态与补偿

| 反馈 | 面向用户的准确解释 | 内部处理 |
| --- | --- | --- |
| 视频排队/处理中 | 后台继续执行，可以离开页面 | 核对调度、到期时间、配置版本 |
| 待核对/unknown | 服务商受理结果尚未确认，积分暂保留 | 按运维流程核对原账号，不能承诺立即重提/退款 |
| 明确失败/refunded | 任务未完成，已按原消费返还应用积分 | 核对原扣费/补偿关联，不人工再加一次 |
| 成功/settled | 真实视频已归档并结算 | 若不可播放，查 Storage/作品链接；不能凭播放问题退款 |
| 付款成功未到账 | 正在核对支付与权益记录 | 验签/查交易、事件及原子入账，重复通知可恢复 |
| 模型未启用/积分不足/限流 | 按实际错误说明 | 不要求用户提供模型 Key，不让用户尝试伪造退款 |

工单收集用户 ID、任务/订单号、时间、客户端错误、是否已重试、积分影响和授权截图。禁止索取密码、完整 JWT、支付私钥或模型 Key。每次处理记录负责人、证据、决策和最终状态；财务异常交财务与运维核对。

视频积分释放与支付现金退款分开。当前没有完整商户现金退款闭环，不把积分补偿说明成“原路退钱”；现金争议由商户侧按订单和实际交易处理，另记录权益一致性，不能在客户端输入金额执行。

## 4. 指标口径

| 指标 | 计算方式/数据来源 | 解释边界 |
| --- | --- | --- |
| 新用户激活率 | 同一注册 cohort 内完成首条真实成片用户 / 有效注册用户 | 固定统计窗口，排除测试/演示 |
| 任务完成率 | 同一创建 cohort 中 completed / 已创建计费任务 | 同时报告 pending/unknown，不只筛终态美化结果 |
| 已决任务成功率 | completed / (completed + failed) | 只反映已决任务，不能代替完成率 |
| 积分退款率 | refunded 任务数 / 同 cohort 计费任务数 | 现金退款另列 |
| 等待时长 | 创建到完成、排队、上游、转存 P50/P95 | 分模型/规格/负载，未终态单列年龄 |
| 人工核对率 | needs_attention/unknown 数与最老时间 | 与自动失败分开 |
| 支付入账差异 | 商户成功但本地未 paid/权益未落账订单 | 使用交易与快照，不能靠浏览器结果 |
| 每条接受成片成本 | 同批全部供应商调用/重试/存储等成本 / 人工接受成片数 | 包含失败用量；应用积分不等于供应商价格 |
| 复用/留存 | 同 cohort 后续实际使用用户/初次激活用户 | 日期窗口固定，排除运营代生成 |

CTR=点击/曝光，CVR必须明确是转化/点击还是转化/曝光；汇总按总分子/总分母，不平均百分比。新版DataFeedback仅使用官方自然视频指标（待平台联调）；竞品/选品和旧流量预测仍有模拟内容，不能作为实际经营数据。A/B实验需随机分组、样本量/统计方法和同口径采集，现有页面不等于自动投放实验。

## 5. 成本、定价与预算

当前注册默认20积分，视频默认10积分，图片/封面默认各10积分（`credit_costs`），AI Action按表收费；提示词辅助与直接音频暂不收应用积分，平台仍承担供应商用量。实际价格由配置与任务快照确定。

上线前建立模型/规格/配置版本成本表，逐项记录报价来源日期、币种、token/秒/次的单位、失败与查询是否计费、储存与带宽、支付费、人工核对成本。视频目前单 Action 定价，未按模型分层；不能通过文档写价格实现收费代码。

试点设平台及供应商每日预算、单账号额度、免费能力暴露范围和人工检查频率。现有频控不是金额预算系统；超预算由管理员禁用新生成入口并保留旧任务查询，依 [运维手册](RUNBOOK.md) 处置，不能撤销旧任务密钥。

## 6. 日常、每周与发布运营

每日核对最老待处理/unknown、失败退款、支付权益差异、供应商配额、Storage 转存失败及新增工单。每周按同 cohort 汇总质量接受率、成本、留存与高频原因，形成可追踪需求，不用页面模拟数据补空白。

发布前通知实际变化、停机窗口和受影响功能，说明旧任务处理方式。发布后按配置版本观察，不用混合旧/新供应商结果评估改动。宣传仅使用有证据的界面和成片，标注测试环境、模型与人工处理；规划功能不列为已上线。

商业化里程碑见 [商业化方案](plan/商业化.md)，资金流程见 [支付方案](plan/支付.md)，技术故障由 [运维手册](RUNBOOK.md) 处理。
