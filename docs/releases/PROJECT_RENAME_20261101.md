## 六领域影响

需求与运营统一使用「内容创作平台」名称，用户计费、任务与权益规则不因改名改变。架构与开发仍使用既有 Auth/数据库/Storage/执行器和运行契约，不重建业务数据。测试增加回执迁移检查，并核验实际页面和生产构建。运维使用新开发入口与镜像名，保留原数据、凭据与独立快照。

旧项目名称只保留在许可证、归档证据和统一回执迁移读取中。数据库既有 schema/迁移回执、部署实例名、历史镜像/数据卷、私有状态路径是持久标识，不能靠文本替换重命名。后续清理将新公开配置写为 `__AIGC_RUNTIME__`，前端保留读取 `__SHOPRO_RUNTIME__` 以兼容原部署；详情见 [清理记录](SOURCE_CLEANUP_20261101.md)。

当前操作应使用 [开发指南](../development/DEVELOPMENT_GUIDE.md)、[MCP](../../services/mcp/mcp.md)、[工程目录](../development/PROJECT_STRUCTURE.md) 和本记录。`docs/archive` 及旧官方部署回执中的命令不是当前启动入口。原作者仓库名称属于软件来源，不改写 LICENSE。

## 发布状态与回退

本次更新了工作区和本地开发环境，尚未把改名版本晋级到本地自托管交付或线上 ECS；其 v1.1.0 固定发布身份继续以原回执为准。没有提交、推送、重新命名云资源或修改历史数据库迁移。

发布时先审阅工作区已有其他界面修改，冻结完整源码并生成新载荷/源码摘要，再按 [升级恢复手册](../deployment/SELF_HOSTED_ECS_RUNBOOK.md) 分别验收各环境。正式发布使用标准 Dockerfile 构建并记录镜像摘要；新标签本身不代表镜像内部入口或实际运行实例已更新。

若回退开发环境，需同时恢复目录、TRAE Run/启动器及 Compose 名称，核对原容器 bind mount 后再启动；不能直接启动仍指向旧目录的保留容器。新旧依赖卷是可再生开发依赖，数据库、素材、任务与密钥不参与改名清理。
