# 仓库发布与历史版本管理

更新：2026-10-31。当前生产基线与执行状态见[发布记录](PRODUCTION_BASELINE.md)。目标仓库为GitHub `jelven007/AIGC`、远端`github`、主分支`master`；`origin`属于其他仓库，不能推送。

## 版本身份

首个完整生产基线为`v1.0.0`。`package.json`为版本号唯一来源，`release-identity.json`记录公开版本、Git SHA、源码SHA256和运行契约；完整交付清单绑定文件摘要，运行镜像使用不可变ID。分支或标签不等于环境已升级，发布和环境验收分别记录。

## 合并与发布

1. 读取实时远端，检查累计变更、源目录、秘密排除、依赖锁和文档。
2. 短发布分支提交，经检查后合入`master`；不改写历史，不跳过钩子。
3. 冻结发布产物，完成数据快照及本地/线上升级核验。
4. 推送明确的`github/master`与注释版本标签，用GitHub CLI建立版本发布并附摘要清单。
5. 独立重新读取远端提交、标签、发布记录和两环境公开身份，更新交付回执。

保留当前版本加最多两个历史版本；完整Git祖先始终保留。本次滚动历史目标为`history/v20261027-baseline`（`63ff099`）与`history/v20261022-34`（`d7e3d38`），更旧`history/v20261022-33`只在发布与环境验收后清理。

运行目录采用`releases/current`和两个受控历史目录，清理前检查Compose活动挂载、当前路径和回退记录。开发依赖缓存与数据库/素材备份不计入代码版本数量；数据备份按恢复手册独立管理。未验收候选不得挤掉最后可用回退产物。

回退选择经验证的版本和对应镜像/配置，资金、已受理任务、历史密钥与素材保持。禁止用切换标签、`reset --hard`或删卷恢复业务。操作见[运行手册](../deployment/SELF_HOSTED_ECS_RUNBOOK.md)。
