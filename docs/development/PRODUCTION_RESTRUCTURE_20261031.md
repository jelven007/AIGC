## 目录迁移决定

保留符合现有工具链的前端 `src/`、函数 `supabase/`、执行器 `worker/`、网关 `mcp/` 运行边界，以现有领域分组作为正式源码结构。源码根仅保留运行源码、配置、依赖锁、自动化、测试、当前文档和维护工具；旧后端、实验、调试日志、临时构建、实例状态及离线交付包退出源码目录。

```text
shoproai/
  src/                 前端，页面按业务领域分组
  public/              前端公开静态资源
  supabase/            函数、不可改写的历史迁移与数据库运维 SQL
  worker/              媒体渲染与音视频任务执行器
  mcp/                 同业务 API 的 Agent 网关
  deploy/              环境、容器、资源与调度清单
  scripts/             正式构建、测试、发布、升级与恢复命令
  tests/               单元、协议、数据库、媒体和浏览器验证
  docs/                一套当前全生命周期文档及明确标记的历史证据
  tools/               非运行依赖的维护工具
  package.json         正式版本、依赖及统一命令入口
  pnpm-lock.yaml       唯一前端依赖锁
```

实例配置、密钥、证书、数据库、Storage、媒体工作目录与备份具有独立生命周期。本地活动状态迁出 `shoproai/.selfhost-test-final` 前先备份并记录 Compose 项目、挂载和镜像；更新状态路径后核验原账号、余额及素材。线上继续使用 `/opt/shopro/state`，源码晋级到带版本的 `/opt/shopro/releases/` 目录。

## 发布与历史保留

将首个完整生产基线发布为 `v1.0.0`，使用短期发布分支核对累计变更，再合并 `master`。当前版本与最多两个历史版本分别记录源码 SHA、产物摘要、镜像身份及验证结果。保留完整 Git 提交祖先，不改写历史；滚动清理受控历史标签和应用发布包。数据库/素材备份按独立数据保留规则管理，不把代码版本保留数量误用于财务或业务数据。

GitHub 直连当前不可达，ECS SSH 和 GitHub API 网络已确认可达。先恢复可靠的仓库连接并重新读取实时远端；任何冲突需在最终合并结果上重跑验证。尚未收到远端回执前不标记推送或发布成功。
