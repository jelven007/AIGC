# v1.1.0 生产工程整理与发布计划

状态：实施中。读者：开发、测试、运营、运维与发布维护者。责任：仓库维护者。核对日期：2026-11-01。每次目录、协议或发布步骤变化更新；本计划完成后由当前需求、架构、开发指南、测试计划和发布回执接管权威状态。

源码迁移阶段已完成，见 [目录迁移回执](../development/DIRECTORY_MIGRATION_V1_1_0.md)。远端主线经 GitHub API 与 Git 对象摘要逐项核验后接入独立引用 github-api/master；保留了远端凭据历史清理说明。旧目录采用副本验证后私有隔离，未删除文件。源码、类型、构建、Node、Python/数据库、媒体、MCP和隔离浏览器门禁已取得当前证据；权威文档更新、合并、版本封存、两环境晋级和最终保留清理继续执行。

用户授权范围：重组生产工程目录，按最新源码更新全生命周期文档，清理临时内容，完成仓库合并和新版本发布，升级本地及线上环境，最多保留两个历史版本。本轮使用 v1.1.0，记录工程组织与交付体系变更以及已验证的界面、草稿恢复修复。

## 工程边界

| 区域 | 目标位置 | 责任与迁移约束 |
| --- | --- | --- |
| 前端应用 | apps/web/src、apps/web/public、apps/web/index.html | 保留所有路由、账号隔离与业务行为，统一修正 Vite、TypeScript、规则、测试和发布指纹 |
| 媒体服务 | services/media-worker | 保留 Python/FFmpeg 源码、依赖锁、模型资产及容器内稳定路径 |
| MCP 服务 | services/mcp | 保留工具目录、权限和 API 协议；同步镜像构建与调用路径 |
| 服务平台 | supabase/functions、supabase/migrations、supabase/ops | 平台工具约定的目录保留；数据库历史迁移不改写，纯契约保持单一来源 |
| 部署配置 | infra | 从 deploy 迁移，更新所有 Compose、Dockerfile、自动化脚本与文档引用；原运行数据路径和项目身份保持 |
| 自动化 | scripts | 保持支持的构建、开发、测试、发布、快照、恢复和运维入口，清除一次性脚本进入生产闭包的可能 |
| 测试 | tests | 保留现有可复现测试发现方式，增加目录/构建/交付迁移断言，运行完整受影响门禁 |
| 文档 | docs | 每类只保留一个权威入口，旧时点与探索资料标为归档，不把历史验收当作当前状态 |
| 运行与交付 | 源码外状态目录与 releases | 私有配置、素材、数据库、加密快照独立保留；新版本验收后保留 current 加最近两个历史版本 |

根目录保留标准工具配置、锁文件、README 与协作规则。移除没有源码内容、没有依赖的旧 gitlink。记录迁移前后路径与摘要，使结构变动可以审阅和恢复。

## 文档权威与时效

每个关键文档有读者、责任、源码来源、最后核对日期、复核周期和变更触发条件。相同系统只有一个权威位置；重复说明改为指向权威页，旧版本资料标记非当前。

| 文档 | 类型 | 权威来源 | 复核与失效信号 |
| --- | --- | --- | --- |
| 产品需求 | reference | 实际路由、业务服务、数据事务与本轮用户要求 | 每次行为发布；功能或接受条件改变而正文未更新即失效 |
| 技术架构与 ADR | explanation / architectural | 源码依赖、运行协议、部署边界 | 每次边界变更；源码布局或运行职责漂移即失效 |
| 开发指南 | tutorial | 冻结工具链、锁文件与启动命令 | 每次工具链/路径变更；干净检出无法按文档构建即失效 |
| API、数据与配置 | reference | 服务契约、迁移与配置读取代码 | 每次协议变更；文档与真实字段/权限不一致即失效 |
| 测试计划与回执 | how-to | 实际测试清单、CI、当轮命令结果 | 每次发布；只有历史结果或遗漏新路径即失效 |
| 运营指南 | how-to / operational | 运营页面、服务端权限、任务与账务状态 | 每次运营行为变更或30天；权限/处置步骤变更即失效 |
| 升级恢复手册 | how-to / operational | 实际安装器、快照工具、运行环境 | 每次部署或30天；挂载、协议、恢复步骤改变即失效 |
| 版本与保留 | reference | 版本号、Git、不可变清单和两环境回执 | 每次版本变动；源码/包/运行身份不同即失效 |
