## 1. 核心定位与可销售范围

面向具备商品素材的商家、内容运营与小型团队，优先验证脚本辅助、真实视频任务和成片归档。付费依据是能够交付可接受作品、保持任务/积分可核对，而不是页面数量、模型数量或自动投放故事。

当前官方云端仍旧基线，最新版尚未真实模型验收；因此先做受控试点准备，不将统一模型设置、图片/音频、方舟或火山托管包装为已上线服务。批量、完整剪辑渲染、自动发布、真实竞品数据、后台 RBAC、私有素材等未交付，不进入付费承诺。

## 2. 产品包与收费现状

| 能力 | 当前实现 | 商业决策 |
| --- | --- | --- |
| 套餐/积分包 | plans 与订单快照、原子权益发放 | 收款前验证商户、沙箱、价格与账单；不继承旧宣传价 |
| 视频按次积分 | generate_video 默认 10 积分；一次预占/成功结算/明确失败释放 | 当前未按模型定价；价格需覆盖最贵可启用模型或新增分层实现 |
| 注册体验 | 免费计划默认 20 积分 | 试点预算内提供；赠分不是现金承诺 |
| 文本/图片/音频辅助 | 直接入口暂不收应用积分，有频控 | 平台有供应商成本；正式开放前设预算与合理收费 |
| MCP | 共用业务 API/JWT，视频同规则 | 未形成独立 OpenAPI 商业平台；按同一用户权益处理 |
| 定制/企业 | 私有素材、独立后台、批量等尚缺 | 单独需求、成本、交付/验收，不按现有能力销售 |

模型 API Key 是平台管理员配置的服务端凭据，不要求商家在浏览器上传自己的 Key。不同供应商/模型的成本与权限分开核对。

## 3. 单位经济与预算

每条人工接受成片成本 = 同批全部供应商调用成本（包含失败、未知和重试）+ 存储/带宽 + 支付费 + 客服/核对成本，除以人工接受成片数。不能只算成功任务或把返还积分等同于上游退款。

每月毛贡献 = 实际确认收入 − 同期可归属模型/基础设施/支付等直接成本；另列固定研发、运营与税费，不从积分充值额直接推出利润。套餐收入确认、未消费权益与现金退款规则需财务确定。

建成本台账：供应商、账号/配置版本、规格、报价日期/单位/币种、实际账单、失败收费、接受率、流量/储存、人工时间。价格采用场景预算测算，不写未经验证的“每条几分钱、毛利百分之多少”。

每日预算、供应商余额/限额、免费辅助入口用量、单账号额度和异常账户人工复核须在试点前确定。当前频控不是金额预算引擎；临时禁用新任务仍保留旧版本凭据以便查询。

## 4. 试点与增长实验

| 阶段 | 进入条件 | 工作 | 退出证据 |
| --- | --- | --- | --- |
| A 技术准入 | 后端版本匹配、模型账号/额度明确 | 登录/隔离/视频成功与失败/配置变更/关页验收 | TEST_PLAN 对应必需用例通过，任务/账单证据 |
| B 受控商家试点 | 素材授权、预算、客服负责人明确 | 收集真实任务、人工质量判定、耗时与成本 | 可复现作品、差异归因、接受率/成本样本 |
| C 收款验证 | 支付沙箱/回调、权益、合同/价格明确 | 小范围实际套餐收款与对账，记录退款边界 | 订单/权益/渠道一致，无未处理资金差异 |
| D 扩大开放 | 达到团队确认的质量/成本/恢复标准 | 渠道实验、留存与加载/容量评估 | 按 cohort 的留存/收入/成本，不用模拟看板 |

试点人数、周期、预算和成功阈值由负责人根据资源确认；本文件不伪造已招募客户或固定完成日期。先使用现有商家网络与可复现案例；每个渠道记录实际获客成本、激活与留存，未验证前不承诺裂变/分佣收益。

## 5. 风险与客户沟通

供应商权限/价格改变、未知受理、公开存储、同步请求无法恢复、现金退款闭环不足和部署版本差距是当前实质边界。运营公开描述已验收模型/规格、计费、失败补偿、服务时段与素材访问方式；不承诺自动转化、语言质量、无限生成或统一 SLA。
