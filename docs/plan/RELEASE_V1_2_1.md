## 发布管线与固定输入

最新源码/文档审阅→受影响测试→release/v1.2.1提交→master快进合并→固定提交构建一次→双架构封存与附件→注释标签/GitHub正式发布→本地冷快照/升级/接受→ECS相同前端与Edge晋级→开发核验→回执/保留/临时清理。

| 输入或依赖 | 固定与可用性 | 缺失时行为 |
| --- | --- | --- |
| 源码 | 固定提交、555以上实际源码文件摘要与干净工作树；数量以清单为准 | 停止构建 |
| Node/pnpm/依赖 | Node22.23.4、pnpm10.34.5、根锁；既有依赖卷只读 | 停止，不回退联网浮动版本 |
| 前端/Edge产物 | 新空输出目录，network=none，43函数bundle；两端相同字节 | 停止晋级 |
| 原生执行镜像 | arm64/amd64各自固定ID；实际Python代码、锁、模型摘要验证 | 停止，不接受架构或源码漂移 |
| 状态/回退 | 原SOURCE_DIR、私有配置、当前数据库、冷快照与v1.2.0载荷 | 停止升级 |
| 发布远端 | 非强制更新清理后master、固定注释标签、附件独立下载校验 | 保持原环境，定位连接或权限原因 |

发布构建不复用前端输出缓存；新目录构建是缓存未命中路径。只复用声明的固定依赖层，逐文件摘要与镜像真实代码检测过期输出。SOURCE_DIR、build-source、source-manifest、runtime-images和release-identity共同追踪身份。双架构差异仅允许镜像清单及其清单摘要；前端/Edge不能分别重建。

同一时刻只有一个正式候选；已有未提交v1.2.1仅为初步接受，不等同注释标签的固定提交。新候选不得越过失败阶段；远端并行更新须整合后重新审阅与构建，不强推。release分支用于当轮固定与回退，后续回执独立提交，不移动标签；无紧急旁路或长期并行发布线。

## 门禁、晋级与回退

必需：结构/链接、版本策略、typecheck、lint、build、模型Node与密钥回归、真实PostgreSQL自建配置、发布闭包、隔离浏览器六类创建/保存/刷新及scope回归、固定源码/产物/镜像摘要、公开标签/附件回读。独立CI由合并触发，实际状态记录，不用本地结果冒充CI。

每环境升级前认证五对象冷快照并记录原账号、余额、旧成片SHA256、JWT、密钥环、私有身份与容量。先本地接受，再ECS同一载荷；两环境check须有67迁移/最新00069、43Edge与00068/probe24/render4/edit2。已有00069只验证账本，不重新改写迁移。

三环境分别使用1440px/390px真实登录检查分类文案、13内置入口、六类新建弹窗、取消、刷新与重载，再以实际HTTP模块/部署载荷摘要交叉验证。线上创建SQL仅BEGIN/ROLLBACK事务，无持久验收配置，无付费供应商生成。实际线上成功创建/保存API未直接写入，夹具覆盖与真实数据库覆盖分开记录。

停止条件：配置/源包/镜像不匹配、迁移摘要变化、原资产或余额变化、页面/API异常、容量改变。代码回退先验证v1.2.0与追加00069兼容；不覆盖原库或删卷。五对象认证不冒充完整新卷恢复演练，商业质量和SLA独立接受。

发布维护者负责版本、固定构建、远端与证据；运维维护者接手快照、升级、监看与回退。升级窗口观察健康、登录、旧视频、最老UNKNOWN与告警新鲜度；异常立即停止后续晋级/清理。
