# 批量视频任务与预算

日期：2026-10-21。迁移 `00038_batch_video_orchestration.sql`，接口 `batch-video-jobs`，页面 `/batch-create`。本轮是源码与本地验证，未部署云端、未调用真实收费模型。

## 已交付行为

每批选择 1–50 个本人商品，可设置模型、风格、语言、画幅、分辨率和时长，以及单品补充描述。服务端读取商品资料，将事实与生成要求保存为子任务快照；商品图作为首帧，采用原有模型能力校验与私有素材授权，不将浏览器传入商品事实视为可信来源。

整批创建在一个 PostgreSQL 事务内完成。读取真实单价，核对用户确认的价格与预算、有效专业版/企业版套餐、余额和最多 5 个活跃批次，再复用 `create_video_job` 创建作品、子任务、逐笔扣费与配置版本。任一失败会回滚整个批次，不留下部分扣费或孤立作品。每个子任务有独立原始扣费，批次预算不是额外再扣一次。

同一用户、同一 `request_key` 和完整参数只创建一次；参数变化拒绝。创建响应丢失先读取既有批次，找回不受后来商品删除或模型停用影响。页面保存未确认请求回执，刷新后只能继续原请求，服务确认后删除回执；网络故障不生成新 UUID。积分刷新期间套餐组件保留已确认的当前用户权限状态，避免卸载任务页面；服务端仍独立校验套餐。

子任务由现有后台视频 Worker 领取，页面只读取进度。批次状态、成功/失败/取消数、待核对数、预占/已结算/已返还积分全部由子任务汇总，不依靠浏览器修改计数或状态来执行任务。

## 暂停、取消与结果

| 操作/情况 | 行为 |
| --- | --- |
| 暂停 | 锁父批次，阻止后续 queued 子任务领取；已经提交或已有结果证据的任务继续查询/归档 |
| 恢复 | 未取消批次恢复后续领取；不重新预占，不重建子任务 |
| 取消 | 父批次排他锁与子任务领取共享锁协调；仅尚未提交、无上游 ID 的 queued 子任务按原流水返还 |
| 正在提交/已受理 | 取消后仍保留原任务和预占，完成则结算，明确失败则返还 |
| 受理未知 | 保留待核对与预占；必须用原核对接口及证据恢复，取消不能替代未受理证据 |
| 退款写入故障 | 取消事务整体回滚，可刷新并重试；重复取消只释放一次 |
| 部分成功 | 全部结束后 `partial`，保留成功成片与失败/取消明细 |
| 旧批次 | 没有执行器或计费关联的旧活跃记录标记失败，不自动恢复或扣费 |

内部父表仅保留控制意图，展示终态由 `batch_video_snapshot` 汇总。集成者不能仅依据 `batch_jobs.status` 判断全批生成结果。任务中心也识别取消子任务，首页恢复到取消任务时清理本地回执。

## 接口

POST `${SUPABASE_URL}/functions/v1/batch-video-jobs`，用户 JWT 或有效 API Key：

| Action | 参数 | 权限/输出 |
| --- | --- | --- |
| quote | 无 | `video:read`；`unit_cost/max_items/max_active_batches` |
| create | `request_key/name/provider/product_ids/settings/overrides/expected_unit_cost/budget` | `video:create`；HTTP 202 `{batch}` |
| list | 无 | `video:read`；最近 20 个批次和最多 50 条子任务 |
| query | `batch_id` 或 `request_key` | `video:read`；本人 `{batch}`，纯读取 |
| pause/resume/cancel | `batch_id` | `video:create`；服务端事务 `{batch}` |

`settings` 为 `duration/ratio/resolution/style/language`，`overrides` 为商品 ID 到 `{prompt}` 的映射。单价更新或配置竞争返回409，余额不足402；503是结果未确认，不是“未扣费”。API Key 权限仍是上一轮的 `video:create/video:read`，网关 `verify_jwt=false`，函数内验证 JWT/Key。客户端禁止直接写批次和子任务表，关键 RPC 仅 service_role 执行。

- 8 个真实 PostgreSQL 用例通过：整批预算/单价/商品权限、套餐到期/余额、并发创建、配置/商品变化后恢复、暂停/已受理继续、取消退款故障回滚/只退一次、未知受理核对、取消领取竞态。
- 5 组服务端模块 + SDK/fetch 夹具通过：参数/事实快照、真实用户/版本/价格、请求恢复、错误状态与隔离、Key权限与取消故障。
- 2 组真实浏览器 + API 夹具通过：390px 创建故障/刷新/同键恢复、暂停恢复、取消失败保留状态/成功显示退款，无页面异常和横向溢出。
- 既有33项资金与任务数据库、16项视频API、8项任务中心回归通过；TypeScript、Biome、ast-grep规则、Vite构建及Deno入口检查通过。宿主Deno二进制不可执行后改用Deno 2.2.6容器完成检查。

## 发布与边界

先应用00038，再同步部署 `batch-video-jobs`、更新共享 Worker 模块及 `video-jobs/video-job-worker`，核对两份网关配置，最后发布前端。继续使用现有视频后台调度，不新增第二套模型执行器。开启云端前验证批次预算与余额、两个用户隔离、关页执行、暂停取消竞态、成片与供应商账单。

已支持一商品一条模型视频；尚不是自动脚本→多镜头→配音→字幕→混剪→多平台发布的一次编排。语言/风格是生成提示，不能保证模型准确生成字幕、翻译或配音；背景音乐和字幕应在剪辑工程中加工。原15–60秒滑块没有对应模型支持，现按2–15秒以及模型归一化规则处理。Sora、多格式导出、音频/数字人后台任务、真实分析/情报/RAG、广告归因/后台和完整云端验收继续推进。
